PatchLLM: Interactive Codebase Refactoring & Patching CLI Agent

Terminal-based coding agent with human-in-the-loop patch approval, dynamic AST scopes, and resilient session checkpointing

Problem & Challenges

Autonomous coding agents frequently make hallucinated edits across entire repositories or produce monolithic diffs that are difficult to verify, leading developers to reject AI-generated code due to lack of granular step-by-step control, scope fencing, and rollback capabilities.

Engineered Solution

Modular interactive agent architecture decoupling Task Formulation (/task), Step-by-Step Plan Generation (/plan), Targeted Context Ingestion (@git:staged, @dir:src), Sandboxed Diff Execution (/run), and Interactive Human-in-the-Loop Patch Approval (/approve, /revert). Built on top of a resilient session checkpointing state machine, LiteLLM multi-provider abstraction, and an asynchronous terminal TUI.

Technical Architecture

PatchLLM executes a structured 4-tier interactive refactoring lifecycle: Tier 1 ingests user goals and expands dynamic context scopes (@git:staged, @dir, @file) while budgeting AST token bounds, Tier 2 generates atomic steps with stateful session serialization and crash recovery (.patchllm/sessions/*.json), Tier 3 invokes foundation models via a LiteLLM multi-provider router to synthesize and dry-run validate unified git diffs, and Tier 4 presents interactive diffs for granular user approval, atomic disk writes, and instant 1-key rollback snapshots (/revert):
